Welcome to Your NestJS Journey

NestJS is a progressive Node.js framework for building efficient, reliable, and scalable server-side applications. It uses modern JavaScript, is built with TypeScript, and combines elements of Object-Oriented ProgrWamming (OOP), Functional Programming (FP), and Functional Reactive Programming (FRP).

Why NestJS?

While Node.js has great tools like Express, they don't inherently solve the problem of architecture. NestJS provides an out-of-the-box application architecture heavily inspired by Angular, allowing developers to create highly testable, scalable, and loosely coupled applications.

Foundational Architecture & Setup

Concept Explanation

NestJS revolves around three main pillars: Modules, Controllers, and Providers.

A Module is a logical boundary that groups related components. Every application has a root module (`AppModule`). Providers are plain JavaScript classes (like services) annotated with `@Injectable()`. NestJS uses Dependency Injection (DI) to automatically instantiate and pass these providers into classes (like Controllers) that need them.

Real-World Example

To start, we use the powerful Nest CLI to scaffold a project. Under the hood, NestJS abstracts Express (by default) to handle HTTP requests.

terminal 
npm i -g @nestjs/cli
nest new my-nest-app

`NestFactory.create()` to bootstrap the application.

app.service.ts
import { Injectable } from '@nestjs/common';

@Injectable()
export class AppService {
  getHello(): string {
    return 'Hello World!';
  }
}

Practical Exercise

1. Scaffold a new project.
2. Use the CLI generator to create a new "Users" module: nest g module users.
3. Notice how the CLI automatically imports `UsersModule` into your root `AppModule`.

Building a RESTful API

Concept Explanation

Controllers handle incoming HTTP requests and return responses to the client. You define routes using decorators like @Get(), @Post(), @Put(), and @Delete(). To extract data from the request, NestJS provides decorators like @Param() for URL parameters (e.g., `/users/:id`), @Query() for query strings, and @Body() for JSON payloads.

Real-World Example

Here is a basic `CatsController` that handles GET and POST requests.

cats.controller.ts 
import { Controller, Get, Post, Body, Param } from '@nestjs/common';

@Controller('cats')
export class CatsController {
  
  @Post()
  create(@Body() createCatDto: any) {
    return 'This action adds a new cat';
  }

  @Get(':id')
  findOne(@Param('id') id: string) {
    return `This action returns cat #${id}`;
  }
}
users.service.ts
@Injectable()
export class UsersService {
  private users = [];

  findAll() { return this.users; }
  
  create(user: any) {
    this.users.push(user);
    return user;
  }
}

Practical Exercise

Generate a controller and a service for your Users module using nest g resource users. Implement endpoints to Get All, Get One by ID, Create, Update, and Delete in memory using an array. Note the order of routes matters: static routes should be placed before dynamic parameterized routes to prevent route interception.

Data Validation & Error Handling

Concept Explanation

Data Transfer Objects (DTOs) define how data is sent over the network. NestJS combines DTO classes with class-validator and class-transformer libraries to automatically validate incoming payloads.

For error handling, NestJS provides a built-in exceptions layer. If a resource isn't found, you can simply throw a NotFoundException, and NestJS will automatically format an appropriate JSON HTTP 404 response for the client.

Real-World Example

create-user.dto.ts 
import { IsEmail, IsNotEmpty, IsEnum } from 'class-validator';

export class CreateUserDto {
  @IsNotEmpty({ message: 'Name should not be empty' })
  name: string;

  @IsEmail()
  email: string;

  @IsEnum(['INTERN', 'ENGINEER', 'ADMIN'], { message: 'Valid Role Required' })
  role: string;
}

optional while retaining validation rules.

main.ts
import { ValidationPipe } from '@nestjs/common';

async function bootstrap() {
  const app = await NestFactory.create(AppModule);
  app.useGlobalPipes(new ValidationPipe({
    whitelist: true,
    forbidNonWhitelisted: true,
    transform: true,
  }));
  await app.listen(3000);
}

Practical Exercise

1. Install packages: npm i class-validator class-transformer.
2. Enable global validation in `main.ts` using app.useGlobalPipes(new ValidationPipe()).
3. Update your `UsersController` to accept a `CreateUserDto` and watch NestJS reject invalid payloads automatically!

Database Integration

Concept Explanation

NestJS is database-agnostic. While it natively supports TypeORM and Mongoose, Prisma has emerged as a highly recommended Next-Gen ORM because of its exceptional type safety and autogenerated client.

Integrating Prisma involves generating a Prisma client from a schema file, and creating a globally available `DatabaseService` in NestJS that extends `PrismaClient`.

Real-World Example

A `schema.prisma` file models your data. Here is an example of an `Employee` model:

schema.prisma 
model Employee {
  id    Int     @id @default(autoincrement())
  name  String  @unique
  email String  @unique
  role  Role    // Enum: INTERN, ENGINEER, ADMIN
}

your application controllers to execute queries safely.

database.service.ts
import { Injectable, OnModuleInit } from '@nestjs/common';
import { PrismaClient } from '@prisma/client';

@Injectable()
export class DatabaseService extends PrismaClient implements OnModuleInit {
  async onModuleInit() {
    await this.$connect();
  }
}

Practical Exercise

Sign up for a free serverless Postgres database (like Neon). Initialize Prisma (npx prisma init) and define your model. Generate the client and create your `DatabaseService`. Inject it into your controller to replace the hard-coded in-memory arrays.

Advanced Configurations & Security

Concept Explanation

Moving into production means securing your API. NestJS makes it easy to enable CORS (Cross-Origin Resource Sharing) globally to accept frontend requests.

You also need Rate Limiting to prevent abuse. NestJS provides the @nestjs/throttler package. Furthermore, modifying the Request/Response lifecycle via Interceptors and Exception Filters gives you absolute control over application logging and error formatting.

Real-World Example

Adding a rate limiter is as simple as registering the module and configuring time-to-live (ttl) limits:

app.module.ts 
import { ThrottlerModule, ThrottlerGuard } from '@nestjs/throttler';
import { APP_GUARD } from '@nestjs/core';

@Module({
  imports: [
    ThrottlerModule.forRoot([{
      ttl: 60000, // 1 minute
      limit: 10,  // Max 10 requests per minute
    }]),
  ],
  providers: [
    { provide: APP_GUARD, useClass: ThrottlerGuard }
  ]
})
export class AppModule {}
security.ts
// Inside main.ts
app.enableCors();
app.setGlobalPrefix('api');

Practical Exercise & Capstone

Secure your API. Run app.enableCors() in your `main.ts`. Then, implement the ThrottlerModule to prevent brute-force attacks. As a final capstone challenge, build a custom ExceptionFilter to catch database errors (like a Prisma duplicate key error) and format the JSON response gracefully for your frontend.
