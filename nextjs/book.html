1. Routing & Layouts (App Router)

👋 Intro

Next.js 13+ introduced the App Router, which uses a file-system based routing mechanism. Folders define routes, and special files define UI.

📖 Explanation

In the app directory, a folder name becomes the URL path. Inside that folder, a page.tsx makes the route publicly accessible. layout.tsx wraps pages to share UI (like navbars) without re-rendering.

💻 Examples

Example 1: Basic Page (app/about/page.tsx)

export default function AboutPage() { return <h1>About Us</h1>; }

Example 2: Dynamic Route (app/users/[id]/page.tsx)

export default function UserPage({ params }: { params: { id: string } }) { return <h1>Profile for User: {params.id}</h1>; }

Example 3: Shared Layout (app/layout.tsx)

export default function RootLayout({ children }: { children: React.ReactNode }) { return ( <html> <body> <nav>My Global Navbar</nav> {children} </body> </html> ); }

🌍 Real-world Use Case

Creating a dashboard where a sidebar is defined in app/dashboard/layout.tsx and remains static, while clicking links loads different views (page.tsx) seamlessly.

🧠 Mini Exercise

Task: How do you create a route for a blog post URL like /blog/hello-world?

Show Answer

Create a folder structure: app/blog/[slug]/ and place a page.tsx file inside it. The params.slug will equal "hello-world".

📝 Summary

Folders map to URLs. page.tsx is the unique UI for a route, and layout.tsx is shared UI for multiple routes.

1. التوجيه وتخطيط الصفحات (App Router)

👋 مقدمة

قدم الإصدار 13 وما بعده من Next.js مُوجّه التطبيقات (App Router)، والذي يستخدم آلية توجيه تعتمد على نظام الملفات. المجلدات تحدد المسارات، والملفات الخاصة تحدد واجهة المستخدم.

📖 شرح

في مجلد app، يصبح اسم المجلد هو مسار الرابط (URL). داخل هذا المجلد، ملف page.tsx يجعل المسار متاحاً. ملف layout.tsx يغلف الصفحات لمشاركة واجهة مستخدم (مثل شريط التنقل) بدون إعادة تصييرها.

💻 أمثلة

مثال 1: صفحة أساسية (app/about/page.tsx)

export default function AboutPage() { return <h1>من نحن</h1>; }

مثال 2: مسار ديناميكي (app/users/[id]/page.tsx)

export default function UserPage({ params }: { params: { id: string } }) { return <h1>الملف الشخصي للمستخدم: {params.id}</h1>; }

مثال 3: تخطيط مشترك (app/layout.tsx)

export default function RootLayout({ children }: { children: React.ReactNode }) { return ( <html dir="rtl"> <body> <nav>شريط التنقل العام</nav> {children} </body> </html> ); }

🌍 حالة استخدام واقعية

إنشاء لوحة تحكم حيث يتم تعريف القائمة الجانبية في app/dashboard/layout.tsx وتبقى ثابتة، بينما النقر على الروابط يحمّل وجهات مختلفة (page.tsx) بسلاسة.

🧠 تمرين سريع

المهمة: كيف تنشئ مساراً لمقال في مدونة برابط مثل /blog/hello-world؟

إظهار الإجابة

قم بإنشاء هيكل المجلد: app/blog/[slug]/ وضع ملف page.tsx بداخله. المتغير params.slug سيساوي "hello-world".

📝 خلاصة

المجلدات تترجم إلى روابط. page.tsx يمثل الواجهة الفريدة للمسار، و layout.tsx يمثل الواجهة المشتركة لعدة مسارات.

2. Rendering Strategies (SSR, SSG, CSR)

👋 Intro

Next.js allows you to choose exactly where and when your HTML is generated: on the server per request, on the server at build time, or in the browser.

📖 Explanation

SSG (Static Site Generation): HTML is built once at build time. Best for speed and SEO.
SSR (Server-Side Rendering): HTML is generated dynamically on every request.
CSR (Client-Side Rendering): Using 'use client' to let the browser render interactive components.

💻 Examples

Example 1: SSG (Cached Fetch)

export default async function StaticPage() { // 'force-cache' is default. Data is fetched at build time. const res = await fetch('https://api.example.com/data', { cache: 'force-cache' }); const data = await res.json(); return <div>{data.title}</div>; }

Example 2: SSR (Dynamic Fetch)

export default async function DynamicPage() { // 'no-store' fetches fresh data on every incoming request. const res = await fetch('https://api.example.com/live', { cache: 'no-store' }); const data = await res.json(); return <div>Live price: {data.price}</div>; }

Example 3: CSR (Client Component)

'use client'; import { useState } from 'react'; export default function Counter() { const [count, setCount] = useState(0); return <button onClick={() => setCount(count + 1)}>{count}</button>; }

🌍 Real-world Use Case

An e-commerce site uses SSG for product pages so they load instantly from a CDN, but uses CSR for the "Add to Cart" button to handle user interactions.

🧠 Mini Exercise

Task: What strategy should you use for a user-specific private dashboard?

Show Answer

SSR (Server-Side Rendering) or CSR (Client-Side Rendering) since the data is highly dynamic, private, and shouldn't be cached globally.

📝 Summary

Mix and match rendering strategies per route or component to get the perfect balance of SEO, speed, and interactivity.

2. استراتيجيات التصيير (SSR, SSG, CSR)

👋 مقدمة

يسمح لك Next.js باختيار أين و متى يتم إنشاء HTML الخاص بك بدقة: على الخادم لكل طلب، أو على الخادم وقت البناء، أو في متصفح العميل.

📖 شرح

توليد المواقع الثابتة (SSG): يتم بناء HTML مرة واحدة وقت البناء. الأفضل للسرعة والـ SEO.
التصيير من جهة الخادم (SSR): يتم إنشاء HTML ديناميكياً مع كل طلب جديد.
التصيير من جهة العميل (CSR): استخدام 'use client' للسماح للمتصفح بتصيير المكونات التفاعلية.

💻 أمثلة

مثال 1: موقع ثابت SSG (جلب مٌخزن مؤقتاً)

export default async function StaticPage() { // الافتراضي هو 'force-cache'. يتم جلب البيانات وقت البناء. const res = await fetch('https://api.example.com/data', { cache: 'force-cache' }); const data = await res.json(); return <div>{data.title}</div>; }

مثال 2: خادم ديناميكي SSR (جلب متجدد)

export default async function DynamicPage() { // 'no-store' يجلب بيانات جديدة مع كل طلب قادم. const res = await fetch('https://api.example.com/live', { cache: 'no-store' }); const data = await res.json(); return <div>السعر المباشر: {data.price}</div>; }

مثال 3: جهة العميل CSR (مكون تفاعلي)

'use client'; import { useState } from 'react'; export default function Counter() { const [count, setCount] = useState(0); return <button onClick={() => setCount(count + 1)}>{count}</button>; }

🌍 حالة استخدام واقعية

موقع تجارة إلكترونية يستخدم SSG لصفحات المنتجات ليتم تحميلها فوراً من شبكة توصيل المحتوى (CDN)، ولكنه يستخدم CSR لزر "إضافة إلى السلة" للتعامل مع تفاعلات المستخدم.

🧠 تمرين سريع

المهمة: ما هي الاستراتيجية التي يجب استخدامها للوحة تحكم خاصة بمستخدم معين؟

إظهار الإجابة

SSR (تصيير من الخادم) أو CSR (تصيير من العميل) لأن البيانات ديناميكية جداً، خاصة، ولا ينبغي تخزينها مؤقتاً للجميع.

📝 خلاصة

يمكنك الدمج بين استراتيجيات التصيير لكل مسار أو مكون للحصول على التوازن المثالي بين الـ SEO، السرعة، والتفاعلية.

3. Data Fetching & Server Actions

👋 Intro

Next.js simplifies backend integration. You can fetch data directly in Server Components and mutate data securely using Server Actions.

📖 Explanation

Instead of creating separate API endpoints for simple form submissions, Server Actions let you write backend functions that can be called directly from your React components.

💻 Examples

Example 1: Direct Database Fetch

import { db } from '@/lib/db'; export default async function UserList() { const users = await db.query('SELECT * FROM users'); return <ul>{users.map(u => <li key={u.id}>{u.name}</li>)}</ul>; }

Example 2: Server Action Definition

"use server"; import { db } from '@/lib/db'; import { revalidatePath } from 'next/cache'; export async function createPost(formData: FormData) { const title = formData.get('title'); await db.insert('posts', { title }); revalidatePath('/posts'); // Refresh the page data }

Example 3: Form invoking a Server Action

import { createPost } from '@/actions'; export default function NewPostForm() { return ( <form action={createPost}> <input name="title" type="text" /> <button type="submit">Save</button> </form> ); }

🌍 Real-world Use Case

A "Like" button on a blog post. The button triggers a Server Action to increment the like count in the database, then automatically updates the UI using revalidatePath.

🧠 Mini Exercise

Task: What directive must be placed at the top of a file or function to turn it into a Server Action?

Show Answer

You must use the "use server"; directive.

📝 Summary

Data flows smoothly. Fetch directly in Server Components, and mutate via Server Actions without the boilerplate of building separate API routes.

3. جلب البيانات وإجراءات الخادم

👋 مقدمة

يسهل Next.js دمج الواجهة الخلفية. يمكنك جلب البيانات مباشرة داخل مكونات الخادم وتعديل البيانات بأمان باستخدام إجراءات الخادم (Server Actions).

📖 شرح

بدلاً من إنشاء واجهات برمجة تطبيقات (API) منفصلة لإرسال النماذج البسيطة، تسمح لك إجراءات الخادم بكتابة دوال خلفية يمكن استدعاؤها مباشرة من مكونات React الخاصة بك.

💻 أمثلة

مثال 1: جلب مباشر من قاعدة البيانات

import { db } from '@/lib/db'; export default async function UserList() { const users = await db.query('SELECT * FROM users'); return <ul>{users.map(u => <li key={u.id}>{u.name}</li>)}</ul>; }

مثال 2: تعريف إجراء خادم (Server Action)

"use server"; import { db } from '@/lib/db'; import { revalidatePath } from 'next/cache'; export async function createPost(formData: FormData) { const title = formData.get('title'); await db.insert('posts', { title }); revalidatePath('/posts'); // تحديث بيانات الصفحة }

مثال 3: نموذج يستدعي إجراء الخادم

import { createPost } from '@/actions'; export default function NewPostForm() { return ( <form action={createPost}> <input name="title" type="text" /> <button type="submit">حفظ</button> </form> ); }

🌍 حالة استخدام واقعية

زر "إعجاب" في مقال بالمدونة. يؤدي النقر عليه إلى تشغيل إجراء خادم لزيادة عدد الإعجابات في قاعدة البيانات، ثم يتم تحديث واجهة المستخدم تلقائيًا باستخدام revalidatePath.

🧠 تمرين سريع

المهمة: ما هي التعليمة التي يجب وضعها في أعلى الملف أو الدالة لتحويلها إلى إجراء خادم؟

إظهار الإجابة

يجب عليك استخدام التعليمة "use server";.

📝 خلاصة

تدفق البيانات أصبح سلساً. اجلب البيانات مباشرة في مكونات الخادم، وقم بتعديلها عبر إجراءات الخادم دون الحاجة للتعقيدات المرتبطة بإنشاء مسارات API منفصلة.
